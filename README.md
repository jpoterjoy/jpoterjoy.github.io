# poterjoy.com

Source for Jonathan Poterjoy's academic website. The site is plain HTML and CSS,
generated by a small Python script from the LaTeX CV, and served by GitHub Pages.

## Updating the site

1. Edit the CV as usual (`../CV-latex/CV.tex`) and recompile the PDF.
2. Rebuild the site:

   ```
   python3 build.py
   ```

   This regenerates everything in `docs/`: publications, talks, group members,
   teaching, current grants, and the downloadable CV all come from the CV.
3. Open `docs/index.html` in a browser to check it, then commit and push.

Use `python3 build.py --cv /path/to/CV.tex` if the CV lives somewhere else.

## Keeping the research page current (about once a year)

Each research theme in `content/research.html` has three layers:

- an opening paragraph on the problem and approach, which rarely needs changes;
- findings from published papers, with citations, which grow when a paper comes out;
- one **Current work** paragraph (`class="now"`), the only part that needs regular review.

Each theme also ends with a "Recent papers" list that the build fills in from the CV. A paper
is assigned to a theme by DOI in `PAPER_THEMES` (in `build.py`), or, if it is not listed there,
by keywords in its title (`THEME_KEYWORDS`), so new papers usually sort themselves. The
`data-reviewed="YYYY-MM"` attribute on each theme records when it was last checked; the build
prints a reminder once a theme is more than a year old. When reviewing, update the Current
work paragraph, move anything newly published into the findings paragraph, and update the
date. Figures from unpublished work are kept off the site by `INCLUDE_UNPUBLISHED` in
`tools/prepare_figures.py`; switch it on once the paper appears.

The About page (`content/about.html`) has a hand-written biography and short bio; its areas of
expertise come from `EXPERTISE` in `build.py`, and the leadership, awards, mentoring, funding,
education, and appointments sections are generated from the CV.

## Group page

Current students, alumni, and thesis titles come from the advising section of the CV, so a
student moves to the alumni list once the CV records their degree. Each current student's
one-line research description is in `STUDENT_TOPICS` in `build.py`, keyed by the name as it
appears in the CV; the build prints a note when a current student has no line. Keep the lines
about the same length (roughly 25 words) and update them when a project changes.

## Profiles and news

Google Scholar, ORCID, and GitHub links are set by `SCHOLAR`, `ORCID`, and `GITHUB` at the top
of `build.py`. An "In the news" section appears on the About page only if stories are listed in
`NEWS` (currently empty).

## Search engines

The build writes `docs/sitemap.xml` and `docs/robots.txt`, gives each page a descriptive title
and summary, and adds schema.org data describing the person (name, position, affiliation, and
areas of expertise) to the home and About pages. After the domain points at GitHub Pages,
verify the site in Google Search Console and submit `https://poterjoy.com/sitemap.xml`.

The home-page photo (`assets/img/hero-arctic.webp`) is "Arctic Sky," taken from USCGC Healy in
the Canada Basin on 19 August 2009 by Petty Officer 3rd Class Patrick Kelley, U.S. Coast Guard
(public domain). The full-resolution original is kept in `../image-sources/`.
`tools/make_hero_scene.py` rebuilds the banner, the image used when the site is shared
(`assets/img/og-banner.jpg`), and the scene data behind the animation (`tools/hero_scene.js`,
pasted into `assets/js/site.js`); the comments at the top of the hero code in `site.js` describe
the camera model, instruments, and forward models.

`docs/wp-content/uploads/2023/06/cv.pdf` is a copy of the current CV so the old
WordPress CV link keeps working.

## Old addresses

`REDIRECTS` in `build.py` lists addresses from the old WordPress site (currently `/publications/`
and one blog post); the build writes a small page at each that forwards to the new site. Any other
missing address shows `404.html`, which uses links from the site root so it displays correctly at
any depth.

## Hosting and launch

GitHub Pages serves the `docs/` folder of the `main` branch. The `docs/CNAME` file holds the
custom domain (`poterjoy.com`).

First-time setup:

1. Create a GitHub repository, commit this folder (`_to_delete/` is ignored), and push it.
2. In the repository's Settings → Pages, deploy from the `main` branch and the `/docs` folder,
   and set the custom domain to `poterjoy.com`.
3. Where the domain's DNS is managed, point `poterjoy.com` at GitHub Pages with four A records
   (185.199.108.153, 185.199.109.153, 185.199.110.153, 185.199.111.153) and add a CNAME record
   for `www` pointing to your `github.io` address. Remove the records that pointed at WordPress.
4. Once GitHub has issued the certificate, turn on "Enforce HTTPS," and verify the domain in your
   GitHub account's Pages settings so no one else can claim it.
5. Make the old WordPress.com site private (or delete it) so it does not compete with the new
   site in search results.
6. Verify the site in Google Search Console and submit `https://poterjoy.com/sitemap.xml`.

After that, publishing an update is: rebuild, check `docs/index.html`, commit, and push.
